## Git workflow

Після кожного завершеного набору змін (апдейту) — автоматично, без
додаткового підтвердження щоразу:

1. `git add` змінені файли (конкретні шляхи, не `-A`/`.` наосліп).
2. Закомітити з коротким змістовним повідомленням у стилі існуючої історії
   (див. `git log`), додаючи `Co-Authored-By: Claude <noreply@anthropic.com>`.
3. `git push origin main`.

Деплой на Vercel — автоматичний через Git-інтеграцію (`.vercel/project.json`
уже прив'язаний до проєкту): пуш у `main` сам тригерить деплой, ручний
`vercel deploy` не потрібен.

Виключення — де все ще треба явно спитати дозволу, як зазвичай:
- force-push, `git reset --hard`, будь-що деструктивне чи важко зворотне;
- зміни, які торкаються секретів, міграцій БД проти прод-проєкту Supabase,
  або оплачуваних/зовнішніх дій.
